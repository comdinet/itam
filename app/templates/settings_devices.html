A machine that reports its own spec through a custom attribute script is shown exactly as it reported it, and nothing is added beside it - a Mac tag that already reads 512G does not need ITAM's opinion on the disk next to it. Everything below is the fallback for machines with no such script, which in practice means Windows:
CPU model — Sync CPU model above, from userExperienceAnalyticsResourcePerformance. It is beta but documented, and application permission is the same DeviceManagementManagedDevices.Read.All the device sync uses. Endpoint Analytics has to be switched on and the machine has to have reported, so a device can be legitimately absent; the result says how many were.
Total RAM — Sync total RAM, one call for the whole fleet. Intune reports 0 for some platforms; the result says how many gave a real number, and the CPU sync fills in any device this one left empty.
Disk — already synced for every managed device, with no extra call and nothing to switch on.
Device inventory — the beta and undocumented endpoint, which refuses an application token on this tenant. It is kept only because it returns more than the three facts above. It is not in the nightly run, and a refusal is reported as a failure rather than as an empty inventory.

A rule for the physical, Intune-managed fleet

Paste into a Dynamic Device group in Entra. Device groups have no rule builder — it is the text box or nothing.

(device.accountEnabled -eq true) -and (device.deviceManagementAppId -eq "0000000a-0000-0000-c000-000000000000") -and (device.deviceModel -notContains "VMware") -and (device.deviceModel -notContains "Virtual")

deviceManagementAppId is the property that means Intune manages this; 0000000a-0000-0000-c000-000000000000 is Intune's own application id (Configuration Manager, for co-managed devices, is 54b943f8-d761-4f8d-951e-9cea1846db5a). Not device.managementType: Microsoft documents that one as "for mobile devices", so it does not match managed Macs or PCs and the group comes back missing the fleet.
A null property makes a comparison false, so a device that has never reported a model is excluded by the -notContains clauses too — check it with Validate rules against one real machine and one VM.

Ignored devices {{ ignore_counts.ignored }} of {{ ignore_counts.total }}

Not everything Intune manages is kit somebody has. Virtual machines live in a group, nobody carries one, and turning each into an asset makes the estate look bigger than it is. Ignored devices are still synced — so what is hidden, and why, is always answerable — but they are kept off this list, never become assets, and are left out of the holder check.
